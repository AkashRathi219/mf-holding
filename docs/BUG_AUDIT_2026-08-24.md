## CRITICAL

### C1. Partial-update PUTs null-out NOT NULL columns or silently wipe holdings [FIXED]
- `webapp/tools_api.py` strategy/model/client/client-portfolio PUT handlers +
  `webapp/userdata.py::update_model/update_strategy/update_client/
  update_client_portfolio`.
- Every update endpoint forwards all keys via `body.get(...)` (omitted → `None`)
  and the store layer writes any key that is *present* in the fields dict.
- Impact: `PUT /api/strategies/{id}` with only `rules_text` → `SET name=NULL`
  → IntegrityError → 500. `PUT /api/client-portfolios/{id}` with
  `{"name":"Renamed"}` → holdings/allocations/kind/strategy_id wiped.
- Fix: store layer now treats `None` as "not provided"; API layer validates
  required `name` and returns 400 instead of leaking a 500.

### C2. `results_cached` never initialized in run_pipeline [FIXED]
- `main.py:478,516`. First sha256 parse-cache hit raises UnboundLocalError,
  swallowed by the per-AMC except → every cached AMC reports "failed" on
  re-runs; monthly retry path defeats itself.

### C3. Misordered NAV histories from fetch_missing_nav mirror + unsorted readers [FIXED]
- `src/fetch_missing_nav.py::_date_key`: month map is numbers→names but input
  months are names, so sort keys are `"2026-Aug-18"` (alphabetical month order).
  Files written via this path (and `nav_daily._full_history_doc`,
  `db._heal_thin_nav_history`) are stored misordered forever.
- Readers trusted `hist[-1]` without sorting:
  `webapp/market_value.py::scheme_latest_nav/_scan_nav_history/_scan_stock_prices`,
  `webapp/data_health.py::_file_freshness`.
- Impact: ETF/backfilled schemes priced against weeks-stale NAVs; stale weights
  persisted into client portfolios via CAS upload; wrong freshness scores.
- Fix: correct name→number map; defensive `_nav_date_key` sort in every reader
  before taking the last element.

### C4. Document re-upload erases stored cash-flow history [FIXED]
- `webapp/tools_api.py` upload path: PDF/holdings-only JSON leaves
  `transactions=[]`, which was then passed unconditionally to
  `update_client_portfolio(transactions=[])` → wipes the previously stored CAS
  transactions (movement analytics silently degrade to `None`).
- Fix: pass transactions through only when non-empty (matches the guarded
  create-path behavior).

### C5. Gold asset class unreachable — double-escaped regex [FIXED]
- `webapp/db.py::portfolio_analysis`: `re.compile(r"\\bgold\\b")` matches only
  the literal text `\bgold\b` (verified live: no match on "Gold BeES ETF").
- Impact: gold funds classified as debt by the fallback → false compliance
  breaches ("Max 30% debt"), asset pie shows Other instead of Gold.
- Fix: single backslashes + regression test pinning the match.

## HIGH

### H1. Rate limiter trusts client-controlled leftmost X-Forwarded-For [FIXED]
- `webapp/ratelimit.py::client_ip`. Behind an appending proxy the first entry
  is attacker-chosen → fresh bucket per request → login brute-force/CPU-
  exhaustion protection decorative; unthrottled waitlist rewrites + R2 uploads.
- Fix: configurable trusted-proxy hop count (`TRUSTED_PROXY_HOPS`, default 0 =
  use socket peer); rightmost XFF entry when hops > 0.

### H2. Superadmin claimable via hardcoded default email [FIXED]
- `webapp/auth.py::_superadmin_emails` defaulted to a committed address;
  registration is open so first-come-claims-admin (pipeline triggers, waitlist
  PII, feedback dumps).
- Fix: no default — empty/unset `SUPERADMIN_EMAILS` means no superadmin
  (startup warning); documented requirement to set the env var explicitly.

### H3. Login user-enumeration via PBKDF2 timing [FIXED]
- Unknown email skipped the 200k-iteration hash entirely. Fix: dummy hash
  against a fixed decoy salt before raising the same generic error.

### H4. AMFI-throttled windows marked done with zero rows [FIXED]
- `src/nav_history.py::backfill`: HTML/throttle response returned `""`
  indistinguishable from an empty window; chunk staged with 0 rows and marked
  done forever (prod incident confirmed in nav_repair docstring).
- Fix: HTML responses raise a distinct signal; chunk not marked done on it.

### H5. Corporate-actions agent wipes history on transient failure [FIXED]
- `src/stock_actions.py` (+ `src/stock_reports.py`): source failure returns
  `[]` which is indistinguishable from "no events", then overwrites the stored
  file while reporting `status:"ok"`. Split ratios lost → future bhavcopy
  re-backfills lose scale correction.
- Fix: merge-with-existing semantics — new data may add/replace per-event, but
  an empty result never shrinks a non-empty stored file; real error status
  propagated.

### H6. Blank NAV chart for every scheme after the first [FIXED]
- `webapp/static/js/app.js::renderSchemeDetail` never reset `navControllers`
  (only `renderSecurityDetail` did) → stale controller repaints scheme A's chart
  into detached DOM; B's pane stays empty until a security visit resets it.
- Fix: reset both caches at the top of `renderSchemeDetail`.

### H7. Event listeners re-attached on every route entry [FIXED]
- `app.js::route()` runs `screen.init()` each time; schemes/securities/compare/
  models screens attach handlers unguarded → N handlers after N visits
  (pagination multi-jump, duplicated racing fetches).
- Fix: one-time wire-guard per screen (pattern already used for bonds).
